## 三、Proposed Changes（改动清单）

### 3.1 新增 `lib/api/water_stats.dart`（数据层）

职责：拉账单 → 筛「直饮机 + 已付款 + 近 7 天」→ 逐单取明细升数 → 按日期聚合。带本地缓存，避免每次刷新都重复请求明细。

**类设计**

```dart
class DailyWater {
  final DateTime day;   // 本地日期 00:00
  final double liters;  // 该日直饮机总升数
}

class WaterStatsApi {
  WaterStatsApi(this._api);         // 复用 AuthProvider 的 ApiClient
  Future<List<DailyWater>> last7Days();  // 近 7 天（含今天），按日期升序
}
```

**实现要点（均可直接落地，无需再决策）**

1. 日期范围：`today = DateTime.now()`；`start = DateTime(today.year, today.month, today.day).subtract(Duration(days: 6))`。
2. 拉列表：`getBillList(page: 0, size: 50)` 起循环，最多 6 页（300 条）；`ctime` 早于 `start` 时提前 `break`（列表按时间倒序）。
3. 过滤（**只留直饮机**）：
   - `status == 3`（用户已选：只算已付款）
   - `msg` 含 `直饮机` 或 `水控`；且**不含** `淋浴`、`水表`（双重保险，防水控类洗澡设备）
   - `ctime` 落在 7 天区间内
4. 明细升数：对过滤后的每单调用 `getBillDetail(id)`，读 `data['bill']['dev']['subs']` 求和 `out`。
   - 并发控制：`Future.wait` 每批 5 个，避免瞬间打爆接口。
   - 失败的单按 0 处理，不影响整体。
5. 本地缓存：`SharedPreferences` key `water_detail_cache_v1`，值为 `{"<billId>": <liters>}`；命中缓存的单不再请求明细。缓存只增不减（账单单号唯一，升数不会变）。
6. 聚合：按 `ctime` 的本地日期归并，返回 7 个 `DailyWater`（无数据的日期补 0），保证柱状图固定 7 根。

### 3.2 修改 `lib/screens/home_screen.dart`（首页看板）

1. 状态字段新增：
   ```dart
   List<DailyWater>? _water;   // null=加载中
   bool _waterFailed = false;
   ```
2. `initState` 里并行触发 `_loadWater()`（不阻塞设备列表渲染）；`RefreshIndicator.onRefresh` 改为同时刷新 `_load()` 与 `_loadWater()`。
3. 在「问候卡」与设备列表之间插入 `_waterCard(theme)`：
   - **第一行**：左「今日饮水」标签 + `xx.x L` 大字（`headlineMedium`，主色加粗）；右侧小字「7天日均 x.x L」。
   - **第二行**：7 根柱子。自绘实现（不引依赖）：
     - 外层 `SizedBox(height: 96)`，`Row` + `Expanded` × 7，间距 8；
     - 每根：`Column` → `Expanded(child: Align(alignment: Alignment.bottomCenter, child: Container(height: 按比例, decoration: BoxDecoration(color: 主色/次级, borderRadius: 6))))` + 下方 `星期X` 文字（11px，今天高亮加粗）；
     - 比例：`h = maxLiters == 0 ? 0 : value / maxLiters * 64`，最小可见高度 3（有数据时）。
   - **第三行（仅当今日 0 且近 7 天全 0）**：显示 `暂无饮水记录`，不显示空柱子。
   - 加载中：卡片内 `SizedBox(height: 120, child: Center(CircularProgressIndicator(strokeWidth: 2)))`；失败：`饮水数据加载失败` + 「重试」小按钮。
4. 数据为空/未登录不报错：`_waterFailed` 仅用于网络异常提示。

## 四、Assumptions & Decisions（假设与决策）

| 项 | 决策 | 依据 |
|---|---|---|
| 直饮机识别 | `msg` 含「直饮机」或「水控」，且不含「淋浴」「水表」 | 首页 `favos` 无设备类型字段；账单 `msg` 真机实测稳定带设备类别 |
| 统计口径 | 仅 `status == 3`（已付款） | 用户选择 |
| 升数来源 | 账单明细 `bill.dev.subs[].out` 求和 | 真机 FULL 响应实测字段 |
| 图表形式 | 近 7 天柱状图 + 今日总量 | 用户选择 |
| 性能 | 明细结果本地缓存（billId→升数），分批并发 5 | 明细为逐单请求，需控制请求量 |
| 文档位置 | `docs/CHANGELOG.md`，版本 `1.0.0+N` 递增 | 用户选择 |

**风险与兜底**：若某天账单明细里 `subs` 为空（例如只按次计费的会话），该单记为 0 升，柱状图仍正常；若接口全失败，卡片显示「加载失败 + 重试」，不影响设备列表。
